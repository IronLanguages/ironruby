**IronRuby 4.0.1** fixes pipes and sockets on macOS, where Puma could not start,
`IO#write_nonblock` on sockets, which cut large responses short, and a SQLite crash on
Linux. All of them were found by [@rubys](https://github.com/rubys) while serving Rails
apps that [Roundhouse](https://github.com/rubys/roundhouse) transpiles to plain Ruby.

### Download

Self-contained: unpack one and run `ir.sh` / `ir.cmd`, `irb`, `igem`. No .NET to install.

- **Windows x64**: `ironruby-4.0.1-win-x64.zip`, with Windows Forms, WPF and
  `Samples\Notepad\notepad.cmd`
- **Linux x64**: `ironruby-4.0.1-linux-x64.tar.gz`
- **macOS arm64**: `ironruby-4.0.1-osx-arm64.tar.gz`

`SHA256SUMS` lists the checksums.

### Fixes

- **Pipes to child processes work on macOS** (#12). Backticks, `%x()`, `IO.popen` and
  `Open3` failed with `Errno::EINVAL`: IronRuby passed Linux's value of `O_CLOEXEC` to
  `pipe2`, and macOS numbers the flag differently. On macOS, `core/io/pipe_spec`,
  `core/kernel/backtick_spec` and `library/open3` now pass.
- **Socket addresses on macOS and the BSDs** (#13). Every address the kernel returned
  (`getsockname`, `accept`, `recvfrom`) raised `unknown address family: 528`, because a BSD
  `sockaddr` starts with a length byte; Puma could not bind. On macOS, ruby/spec
  `library/socket` errors fall from 838 to 178.
- **`IO#write_nonblock` on a socket returns what the kernel took** (#14). It claimed the
  whole string even when the kernel accepted only part of it, and the rest was lost: Puma
  responses larger than the socket's send buffer arrived truncated, on Linux and macOS.
  CI now checks that what `write_nonblock` claims is what the peer receives, on Linux and
  Windows (#15); Winsock takes a non-blocking send whole or refuses it, so Windows did not
  lose bytes.
- **SQLite no longer crashes on Linux once another library has loaded the system SQLite**
  ([SQLitePCL.raw#682](https://github.com/ericsink/SQLitePCL.raw/issues/682)), libvips
  through ruby-vips for one. SQLitePCLRaw's `libe_sqlite3.so` is linked without
  `-Bsymbolic`, so its calls into itself could bind to the other copy, and
  `SQLite3::Database.new` segfaulted. The Linux archive now carries a `libe_sqlite3.so`
  built from the same SQLite 3.53.3 with the same compile options, linked `-Bsymbolic`.
  The release build checks that SQLite reports the same version and options from both, and
  that the rebuilt one still answers with the system's `libsqlite3` preloaded. Windows and
  macOS were not affected.

Linux and Windows behave as in 4.0.0 apart from #14. The full status is in the
[README](https://github.com/Largo/ironruby#status).
